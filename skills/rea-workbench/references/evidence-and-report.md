# 证据规范与报告骨架

REA 的产出价值不在「跑通了」，而在**结论可被第三方复现**。
同一个目标两次分析得到相同 Evidence 哈希，才叫结论；否则叫观察。

---

## 一、证据四要素

每条结论至少挂一种定位锚：

| 锚类型 | 形式 | 适用 |
|---|---|---|
| 地址 | `0x00401A20`（含模块基址） | 原生代码 |
| 偏移 | `<file>+0x1F40` | 文件结构 |
| 符号 | `module!Class.Method` | 托管代码 / 导出表 |
| 字面量 | 原样字符串或其哈希 | 配置、密钥提示、URL |

再加一个 **Evidence ID**。没有 ID 的断言，必须显式标注为推断。

---

## 二、三档结论分级（强制）

| 档位 | 判据 | 写法 |
|---|---|---|
| **已证实** | 有 Evidence ID + 可定位锚 + 可复现命令 | 「已证实：…」 |
| **高置信推断** | 多条间接证据一致，但缺一条直接链 | 「高置信推断：…（依据 A/B，缺 C）」 |
| **未验证假设** | 单一迹象或类比 | 「假设待验：…（需要 X 才能确认）」 |

禁止把后两档写成第一档的措辞。**「疑似」不是弱化词，是必要的精度词。**

---

## 三、静态与动态冲突处理

冲突时不要挑顺眼的那个：

1. 记录两边的原始观察（各自的 Evidence ID）
2. 用 `correlate_static_and_runtime` 对齐
3. 列出可能原因：代码路径未触发、构建产物不同、混淆、观测时机、环境污染
4. **把冲突本身写进结论**——冲突往往指向最有价值的问题（如「线上版本与源码不一致」）

`compare_source_to_bundle` 就是为此存在的：它回答的不是「代码像不像」，而是「线上跑的到底是不是这份源码」。

---

## 四、证据包交付

```bash
# 导出（默认落在 REA 管理的数据目录）
export_evidence_bundle

# 事后取回 / 迁移到另一台机器复现
get_evidence_bundle
import_evidence_bundle
```

交付给他人时说明三件事：**REA 版本**、**provider 版本**、**样本标识（文件名 + 哈希）**。
缺任何一项，对方都无法复现。

---

## 五、报告骨架

```markdown
# <目标名称> 逆向分析报告

## 0. 结论摘要
- 3–5 条要点，每条带结论档位
- 明确「本次能回答什么 / 不能回答什么」

## 1. 沙箱与合规
- 样本来源与授权依据
- 样本哈希、体积、格式
- REA 6.5.0 / Ghidra 12.1.4 / JADX 0.7.1
- 平台：Windows x64，能力边界见附录

## 2. 目标画像
- 格式、架构、语言/框架指纹
- 关键证据锚

## 3. 结构与模块
- 模块/包/类/函数的分层视图（用表）

## 4. 关键路径
- 从入口到目标功能的调用链（附地址/符号）
- 静态与动态的对应关系（若有）

## 5. 发现
| # | 发现 | 档位 | 证据 | 影响 |
|---|---|---|---|---|

## 6. 未解项
- 用 list_unknowns 导出，逐条写「缺什么才能解」

## 7. 复现路径
- 逐条命令，可复制粘贴
- 预期输出与已知偏差

## 8. 附录
- 完整 Evidence ID 列表
- 平台限制说明
```

## 六、长任务的可追踪性

超过十分钟的分析，用未知项台账而不是靠记忆：

```
record_unknown        # 记下还没搞清的点
update_unknown        # 有新线索时更新
list_unknowns         # 定期盘点
verify_unknown_resolution  # 确认真的解了
evaluate_reconstruction_coverage  # 覆盖率评估
```

`build_reconstruction_obligation_ledger` 适合「要重建出一份可编译等价物」的场景：它把「必须还原什么」变成清单，避免凭感觉收尾。

---

## 七、常见错误

| 错误 | 后果 |
|---|---|
| 只写结论不写锚 | 无法复核，等于没做 |
| 把字符串命中当成功能确认 | 误报，最典型的一种 |
| 静态结论写成运行时结论 | 严重，会误导决策 |
| 忽略 provider 版本 | 换机器复现不了 |
| 不做二次运行验证 | 无法排除随机性 |
| 报告里塞满工具输出 | 读者抓不到重点，结论被淹没 |
